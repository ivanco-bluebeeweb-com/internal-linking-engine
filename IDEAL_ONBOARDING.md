# Internal Linking Engine — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md` §9 (приложения без классического
`connect_*` к внешнему сервису). Целевой пользователь: владелец сайта/SEO-менеджер,
который хочет, чтобы перелинковка и CTA-вставка происходили сами, без ручного прохода
по каждой статье.

## 1. "Credential type" — его нет напрямую

Нет `connect_*`. Приложение не хранит внешних credentials — оно работает через уже
подключённый в `sites-registry` сайт (WordPress Hub на старте) и через `site_profile`,
который Webbee получает из Content Strategy Hub. Первое реальное действие —
**включить движок для конкретного сайта** (`enable_site` / первый `scan_site`), не
подключение аккаунта.

## 2. Идеальный флоу

1. **Первое открытие, сайтов ещё нет в реестре** — честный баннер: "Подключите сайт
   через WordPress Hub / зарегистрируйте его в Sites Registry, чтобы Internal Linking
   Engine мог его просканировать" — не молчаливая пустота.
2. **Сайты есть, движок ещё не включён ни для одного** — `Empty` с прямым CTA
   "Включить перелинковку для сайта" → выбор сайта из уже подключённых (не форма
   с нуля — сайт уже существует в другом приложении).
3. **Первое включение = первое сканирование** — идеально: включение сайта сразу
   запускает Content Indexer в фоне, с живым прогрессом ("проиндексировано X из Y
   статей"), и по завершении сразу показывает первый предпросмотр плана перелинковки
   (не просто "готово", а reasonable CTA "Посмотреть предложенные ссылки").
4. **Режим по умолчанию — Review-first** — идеально: явно объяснить ПОЧЕМУ (доверие
   нарабатывается), с прозрачным счётчиком "N успешных подтверждений до Full-auto".
5. **Языковая изоляция видна сразу** — если у сайта несколько языков (Polylang),
   идеально показать это как факт конфигурации ("RU и RO — линкуются раздельно"),
   не прятать это в документации.
6. **Multi-site** — список сайтов с их статусом (включено/выключено, режим, дата
   последнего скана), как у WordPress Hub/Content Strategy Hub.
7. **Диф на превью — самое важное состояние** — идеально: показать diff построчно
   (было → станет), с explicit чекбоксами "применить этот пункт / пропустить", не
   бинарный all-or-nothing apply.
